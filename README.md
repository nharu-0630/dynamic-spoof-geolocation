# Dynamic Spoof Geolocation

A Chrome (MV3) extension that replaces the Geolocation API on a per-tab basis. It can pin
you to a point, drift you along a constant bearing, or run you down the **Tokaido
Shinkansen** on the real track alignment, to a real timetable pattern.

Built with [WXT](https://wxt.dev) + React + TypeScript, managed with pnpm.

## Features

- **Fixed** — report a single latitude/longitude.
- **Moving** — a route of as many waypoints as you like. Click the map to add points, drag
  them to adjust, reorder them, and give each one the speed for the leg leaving it and a
  dwell to stand still on arrival. At the end the route can stop, loop back to the start,
  retrace itself, or carry straight on at a fixed bearing — one waypoint plus a bearing is
  the plain constant-drift case. Position is derived from the clock, so a page polling once
  a second and a page polling fifty times a second see the same track.
- **東海道新幹線 (Tokaido Shinkansen)** — pick a train out of a generated service day and
  ride it: the spoofed position follows the real 515 km alignment between 東京 and 新大阪,
  accelerating out of each station, cruising, braking into the next stop, and standing
  still on the platform for the booked dwell. `coords.speed` and `coords.heading` are
  filled in from the running model.
- **Per-tab settings** that survive navigation inside the tab. Applying or stopping takes
  effect immediately: an open `watchPosition` is moved between the real API and the spoofed
  one in place, so there is no need to reload the page.
- **Map** — a Leaflet map in the popup. Click it or drag the pin to set the coordinates,
  and watch the simulated position move on it: a heading arrow in 移動 mode, the whole
  東海道新幹線 alignment with its 17 stations and a following train marker in 新幹線 mode.
- **Jitter** — optional uniform scatter inside a radius, to look like a noisy fix.
- Runs at `document_start` in the page's own world, so the override is in place before any
  page script can grab `navigator.geolocation`. While a tab is spoofed,
  `navigator.permissions.query({name: 'geolocation'})` reports `granted`.

## Install

```bash
pnpm install
pnpm build
```

Then load `.output/chrome-mv3` as an unpacked extension from `chrome://extensions`
(Developer mode → Load unpacked).

For development with hot reload:

```bash
pnpm dev
```

```
  core/

    shinkansen/
      route.ts           alignment, stations, line speed limits

```

## Where the Shinkansen data comes from

### Route path

`src/data/tokaido-route.json` is generated by `scripts/build-route-data.mjs` from
**OpenStreetMap relation [5263977](https://www.openstreetmap.org/relation/5263977)**
(`東海道新幹線`, `route=railway`, `operator=東海旅客鉄道`).

The relation contains every track on the line — both directions, station throats and
sidings — so the script reconstructs a single running alignment by taking the shortest path
through the way graph from 東京 to 新大阪. That comes out at **515.21 km** against the
published 実キロ of 515.4 km, which is the check that the reconstruction is sound. The
result is simplified with Douglas–Peucker at a 1 m tolerance (6,826 → 2,004 points, 43 kB),
well under GPS noise.

The 17 stations are then snapped onto that polyline; every one lands within 17 m of it, and
their resulting distances from 東京 track the published 実キロ to within 0.06 % — no station
is more than about 280 m out over a 515 km line.

> Route geometry © OpenStreetMap contributors, available under the
> [Open Database License](https://www.openstreetmap.org/copyright).

### Timetable

`src/data/tokaido-pattern.ts` encodes the **12-2-3 ダイヤ** — 12 のぞみ, 2 ひかり and
3 こだま an hour — in force since the 2023-03-18 revision, taken from
[東海道新幹線 § 現行のダイヤパターンと停車駅](https://ja.wikipedia.org/wiki/東海道新幹線)
on Japanese Wikipedia (CC BY-SA 4.0). Train-number blocks come from the same article's
現行の号数の振り方 section.

That published pattern gives, for each hourly slot: the departure minute from the
originating terminal, the arrival minute at the far end, and the stopping pattern across
all 17 stations. It does **not** give intermediate times, so those are reconstructed:

1. Each stop-to-stop leg is run through the model in `core/shinkansen/running.ts` — pull
   away at 0.5 m/s², hold the line speed limit, brake at 0.7 m/s² into the next stop.
   Limits follow 東海道新幹線 § 所要時間と最高速度: 100 km/h 東京–品川, 170/110/200 km/h
   through 品川–新横浜, 285 km/h onward, dropping to 185 km/h through 熱海.
2. A single padding factor is solved for so the legs plus dwells add up to exactly the
   published journey time — real schedules carry several percent of 余裕時分, so a
   generously-timed train cruises below the limit rather than sprinting and then idling.
3. If a train still has time to spare at the padding floor, the surplus becomes a station
   wait at the stations the fast trains run through (小田原, 熱海, 三島, 新富士, 掛川,
   豊橋, 三河安城, 岐阜羽島, 米原) — which is what a こだま being overtaken actually does.
4. Station times are rounded to the minute, the way a printed timetable is.

Trains are laid out across an 06:00–21:30 departure window, 臨時列車 (`◆` in the source
table) only between 07:00 and 20:00, and anything that would still be running after
midnight is dropped, since the line closes overnight. That yields about 227 下り and
224 上り trains a day.

**This is a reconstruction, not the real timetable.** Total journey times and stopping
patterns come from published data and are right; the intermediate times, the choice of
which 「▲」 stations each ひかり calls at, and the 号数 are generated. Some consequences
worth knowing:

- Peak speed lands around 235–250 km/h rather than the 285 km/h line limit. A
  standard-pattern train averages 206 km/h over 515 km including stops, and the model
  spreads its 余裕時分 evenly instead of running flat out and then dawdling.
- Only the 東海道 section is simulated. A train continuing to 岡山 or 博多 is shown ending
  at 新大阪, with its real destination noted alongside.

Re-fetch the geometry at any time with:

```bash
pnpm data:route
```

## Usage

1. Open a page that uses geolocation.
2. Click the extension icon.
3. Pick a mode:
   - **固定** — click the map, drag the pin, or type a latitude and longitude.
   - **移動** — click the map to drop waypoints, drag the numbered pins to move them, and
     use ↑ ↓ ✕ to reorder or remove them. Each waypoint carries the speed for the leg that
     leaves it and an optional dwell. Pick what happens at the end: 終点で停止,
     始点に戻って繰り返し, 折り返して往復, or 方位を保って直進 with a bearing.
   - **東海道新幹線** — pick a direction, filter by 種別, choose a train, then decide
     whether it runs on the real clock (**ダイヤに同期**) or leaves its originating station
     the moment you apply (**いま始発駅を発車**). A time multiplier up to 60× makes a
     two-and-a-half-hour run watchable.
4. Set the reported accuracy, and optionally a jitter radius.
5. **適用** to start, **停止** to hand the tab back to the real API.

While the Shinkansen tab is open the popup shows a live read-out — current speed, position,
distance from 東京, next stop and the full station table with the train's current position
highlighted — alongside the map, which follows the train. 全体 zooms out to the whole run,
and 追従 re-centres after you have panned away.

### Map tiles

The map ships with two layers, switchable from the control in its top-right corner:
[OpenStreetMap](https://www.openstreetmap.org/copyright) standard tiles (worldwide, the
default) and the [地理院タイル](https://maps.gsi.go.jp/development/ichiran.html) 淡色地図
from Japan's Geospatial Information Authority, which is sharper over the Shinkansen route
but only covers Japan. Both are attributed on the map itself, as their terms require. Tiles
are fetched only while the popup is open.

# Dynamic Spoof Geolocation [日本語]

Geolocation API をタブ単位で差し替える Chrome (MV3) 拡張機能です。固定座標、一定方位への
移動に加えて、**東海道新幹線**の実際の線形とダイヤパターンに沿って走行をシミュレートでき
ます。

[WXT](https://wxt.dev) + React + TypeScript、パッケージ管理は pnpm です。

## 機能

- **固定** — 指定した緯度・経度を返します。
- **移動** — 任意の数の地点を並べたルートを走ります。地図のクリックで地点を追加、ドラッグ
  で移動、並び替えと削除も可能で、地点ごとに「次の区間の速度」と「停車時間」を設定できます。
  終点に着いたあとは停止・始点に戻ってループ・折り返して往復・方位を保って直進から選べます
  （1地点＋方位が従来の等速直線移動にあたります）。位置は時刻から計算するため、ポーリング
  間隔によらず同じ軌跡になります。
- **東海道新幹線** — 生成した1日分のダイヤから列車を選んで乗車できます。東京〜新大阪
  515 km の実際の線形をたどり、駅ごとに加速・巡航・減速し、停車時分のあいだはホームに
  停まります。`coords.speed` と `coords.heading` も走行モデルから埋めます。
- **タブごとの設定** — タブ内のページ遷移をまたいで維持されます。適用・停止は即座に反映され、
  実行中の `watchPosition` も本物の API と偽装のあいだでその場で張り替えるため、ページの
  リロードは不要です。
- **地図** — ポップアップ内に Leaflet の地図を表示します。クリックまたはピンのドラッグで
  座標を指定でき、シミュレート中の位置もその場で確認できます。移動モードでは進行方向の
  矢印と予測線、新幹線モードでは東海道新幹線の全線形と17駅、追従する列車マーカーを描画
  します。
- **ゆらぎ** — 指定半径内に一様に散らし、実測のような揺れを再現します。
- ページ自身のワールドで `document_start` に実行されるため、ページのスクリプトが
  `navigator.geolocation` を掴む前に差し替えが完了します。偽装中は
  `navigator.permissions.query({name: 'geolocation'})` が `granted` を返します。

## データの出典

### 経路パス

`src/data/tokaido-route.json` は `scripts/build-route-data.mjs` が
**OpenStreetMap のリレーション [5263977](https://www.openstreetmap.org/relation/5263977)**
（`東海道新幹線`, `route=railway`, `operator=東海旅客鉄道`）から生成します。

リレーションには上下線・駅構内・側線を含む全線路が入っているため、ウェイのグラフ上で
東京〜新大阪の最短経路を取って1本の走行線形を復元しています。結果は **515.21 km** で、
公表されている実キロ 515.4 km と一致します。これが復元の妥当性の検証になっています。
線形は Douglas–Peucker 法で 1 m の許容誤差に簡略化（6,826 → 2,004 点、43 kB）してあり、
GPS の誤差より十分小さい精度です。

17駅はこの線形に投影しており、いずれも 17 m 以内に収まります。そこから求めた東京起点の
距離も公表されている実キロと 0.06 % 以内で一致し、515 km の全長に対して最大でも
280 m 程度のずれに収まっています。

> 経路データ © OpenStreetMap contributors,
> [ODbL](https://www.openstreetmap.org/copyright) にて提供。

### ダイヤ

`src/data/tokaido-pattern.ts` は、2023年3月18日改正以降の **12-2-3 ダイヤ**（1時間あたり
のぞみ12本・ひかり2本・こだま3本）を収めたものです。出典は日本語版 Wikipedia の
[東海道新幹線 § 現行のダイヤパターンと停車駅](https://ja.wikipedia.org/wiki/東海道新幹線)
（CC BY-SA 4.0）、号数の割り当ては同記事の「現行の号数の振り方」節です。

このパターンからは、各時間帯の始発駅発車時刻（分）・終点到着時刻（分）・17駅分の停車
パターンが得られます。一方で**途中駅の時刻は公表されていない**ため、以下の手順で算出して
います。

1. 停車駅間の各区間を `core/shinkansen/running.ts` の走行モデルにかけます。0.5 m/s² で
   加速、線区の最高速度で巡航、0.7 m/s² で減速して次の停車駅へ。速度制限は同記事の
   「所要時間と最高速度」節に従い、東京〜品川 100 km/h、品川〜新横浜 170/110/200 km/h、
   以降 285 km/h（熱海付近は 185 km/h）としています。
2. 区間走行時分と停車時分の合計が公表の所要時間にぴったり一致するよう、余裕率を1つ解き
   ます。実際のダイヤにも数％の余裕時分があるので、時間に余裕のある列車は全力で走って
   待つのではなく、制限速度より控えめに巡航します。
3. 余裕率の下限まで下げてもなお時間が余る場合は、速達列車が通過する駅（小田原・熱海・
   三島・新富士・掛川・豊橋・三河安城・岐阜羽島・米原）での待避時間に振り分けます。
   実際のこだまの待避と同じ挙動です。
4. 駅時刻は、印刷された時刻表と同じく分単位に丸めます。

列車は始発駅 06:00〜21:30 の範囲に並べ、臨時列車（出典表の `◆`）は 07:00〜20:00 のみ、
深夜0時を越えて走る列車は保守間合いのため除外します。結果として下り約227本・上り約224本
になります。

**これは再現であって、実際の時刻表ではありません。** 所要時間と停車駅は公表データに基づく
ので正確ですが、途中駅の時刻、ひかりが「▲」のどの駅に停まるかの選択、号数は生成値です。
把握しておくとよい点:

- 最高速度は 285 km/h ではなく 235〜250 km/h 程度になります。標準パターンの列車は停車
  時間を含めて 515 km を平均 206 km/h で走っており、本モデルは余裕時分を全区間に均等に
  配分するためです。
- シミュレートするのは東海道区間のみです。岡山・博多方面へ直通する列車も新大阪止まりと
  して扱い、実際の終着駅は併記します。

経路データは `pnpm data:route` でいつでも取り直せます。

## 使い方

1. 位置情報を使うページを開きます。
2. ツールバーの拡張機能アイコンをクリックします。
3. モードを選びます。
   - **固定** — 地図をクリック、ピンをドラッグ、または緯度・経度を直接入力。
   - **移動** — 地図をクリックして地点を追加、番号付きピンのドラッグで移動、↑ ↓ ✕ で
     並び替え・削除。地点ごとに次の区間の速度と停車時間を設定します。終点の挙動は
     「終点で停止 / 始点に戻って繰り返し / 折り返して往復 / 方位を保って直進」から選択。
   - **東海道新幹線** — 方向と種別を選んで列車を選択し、実時刻どおりに走らせる
     （**ダイヤに同期**）か、適用した瞬間に始発駅を発車させる（**いま始発駅を発車**）かを
     選びます。最大60倍速にすれば2時間半の行程も短時間で確認できます。
4. 精度（m）と、必要ならゆらぎ範囲を設定します。
5. **適用** で開始、**停止** で実際の API に戻します。

東海道新幹線タブを開いているあいだは、現在速度・座標・東京起点キロ程・次の停車駅と、
現在位置を強調した駅時刻表がリアルタイムに表示され、地図は列車を追従します。「全体」で
全区間にズームアウト、「追従」で列車位置に戻ります。

### 地図タイル

地図右上のコントロールで2種類のレイヤを切り替えられます。既定は
[OpenStreetMap](https://www.openstreetmap.org/copyright) の標準タイル（全世界）、もう一方は
国土地理院の[地理院タイル](https://maps.gsi.go.jp/development/ichiran.html)淡色地図で、
新幹線沿線は見やすいものの日本国内のみの提供です。いずれも規約どおり地図上に出典を表示
しています。タイルの取得はポップアップを開いているあいだだけ行われます。
